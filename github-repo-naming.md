# 📦 GitHub Repository Naming Conventions

This document contains my personal notes and guidelines for naming GitHub repositories in a clean, professional, and scalable way as a web developer.

---

# 🧠 1. Feature-Based Naming

Used when the repository represents a single feature, app, or project.

### Examples:
ecommerce-nextjs  
chat-app-socketio  
portfolio-2026  
blog-ssr-nextjs  

### When to use:
- Full projects  
- Practice apps  
- Feature-based learning projects  

---

# ⚙️ 2. Tech + Purpose Format (BEST PRACTICE)

Most professional and widely used in real-world development.

### Examples:
nextjs-ecommerce-app  
react-dashboard-admin  
nestjs-auth-api  
mongodb-crud-app  

### When to use:
- Production-ready applications  
- Freelance/client projects  
- Portfolio projects for hiring  

---

# 🚀 3. Product-Style Naming (PRO LEVEL)

Used when making projects look like real SaaS products or startups.

### Examples:
taskify-app  
devspace-dashboard  
hirehub-platform  

### When to use:
- SaaS applications  
- Startup ideas  
- Branding-focused projects  
- High-quality portfolio projects  

---

# 📌 My Naming Principles

- Keep names clean and readable  
- Use lowercase with hyphens (-)  
- Avoid random or vague names  
- Make purpose clear from name  
- Include tech stack when needed  

---

# 🎯 Why This Matters

Good repository naming helps to:

- Improve GitHub profile quality ⭐  
- Make projects look professional 💼  
- Help recruiters understand projects quickly 👀  
- Organize learning and production code clearly 📂  
- Build strong developer branding 🚀
